# Workflow Builder UX Redesign Specification

## The Problem

The current workflow editor suffers from spatial claustrophobia. It's crammed into:

1. **Creation Modal** - A 800px max-width modal where the workflow editor is just another form field, competing with branch names and task descriptions for vertical space
2. **Settings Page** - A nested modal within a modal, where the pipeline viewer gets a measly `max-height: 350px`

The result: users can't see their workflow. They're editing through a keyhole.

---

## Design Philosophy

This redesign follows three principles:

1. **Full-stage takeover** - Workflow building is a compositional act. Give it the full screen.
2. **Floating action, fixed canvas** - The canvas is sacred. Actions float above it, never stealing layout space.
3. **Visual grammar** - The START/END pipeline metaphor is strong. Amplify it with bold spatial treatment.

---

## Solution: Full-Screen Workflow Builder

### The Pattern: Staged Navigation

Instead of cramming the workflow editor into existing modals, we create a **full-screen workflow builder** that takes over when editing workflows.

```
+------------------------------------------------------------------+
|                                                                  |
|  [Back]                 WORKFLOW BUILDER              [Save]     |
|                                                                  |
+------------------------------------------------------------------+
|                                                                  |
```

## Layout Architecture

### For Super Minion Creation Flow

**Current Flow:**
```
Modal opens -> Form with cramped workflow editor inline
```

**New Flow (Two-Stage Wizard):**
```
Stage 1: Quick Config Modal
  - Project selector (if multiple)
  - Branch short name
  - Goal description
  - Workflow template selector
  - [Edit Workflow] button -> Stage 2
  - [Create with Default Workflow] button -> Done

Stage 2: Full-Screen Workflow Builder
  - Full viewport workflow canvas
  - Floating "+" FAB for adding steps
  - [Back] returns to Stage 1
  - [Save & Continue] returns to Stage 1 with modified workflow
```

### For Settings Page Templates

**Current Flow:**
```
Settings page -> Click "Edit" -> Small modal opens with cramped editor
```

**New Flow:**
```
Settings page -> Click "Edit" -> Full-screen workflow builder slides in
  - Same full-screen canvas
  - [Cancel] returns to Settings
  - [Save Template] saves and returns
```

## Interaction Patterns

### Adding Steps

1. User clicks floating "+"
2. Popover appears with 2x2 grid of step types
3. User clicks desired type
4. New step appears at END of pipeline with enter animation
5. Pipeline scrolls to show new step
6. Popover closes

### Reordering Steps

- Keep existing up/down chevron buttons on each card
- Add subtle drag handle on left edge (for future drag-and-drop)

### Grouping as Parallel

- Select 2+ steps (click with Cmd/Ctrl held)
- Floating action bar appears at bottom: "Group as Parallel"
- Clicking creates parallel group

### Editing Step

- Click step card to expand inline editor
- Edit name, description
- Click "Done" or click outside to close

### Deleting Step

- Hover reveals X button on top-right of card
- Click X removes step with exit animation

## Integration Points

### Dashboard.tsx Changes

```tsx
// Add state for workflow editing
const [workflowEditMode, setWorkflowEditMode] = useState<'none' | 'editing'>('none')

// In the render, conditionally show full-screen builder
{workflowEditMode === 'editing' && formData.workflow && (
  <WorkflowBuilderPage
    workflow={formData.workflow}
    subagentTypes={subagentTypes}
    onSave={(updatedWorkflow) => {
      setFormData(prev => ({ ...prev, workflow: updatedWorkflow }))
      setWorkflowEditMode('none')
    }}
    onCancel={() => setWorkflowEditMode('none')}
    title="Configure Workflow"
  />
)}

// In the form, replace inline editor with button to open builder
{formData.isSuper && formData.workflow && (
  <div className="form-group">
    <label>Workflow</label>
    <div className="workflow-preview-card">
      <div className="workflow-preview-info">
        <span className="workflow-preview-name">{formData.workflow.name}</span>
        <span className="workflow-preview-count">
          {getStepCount(formData.workflow)} steps
        </span>
      </div>
      <button
        type="button"
        className="edit-workflow-btn"
        onClick={() => setWorkflowEditMode('editing')}
      >
        Edit Workflow
      </button>
    </div>
  </div>
)}
```

## Visual Hierarchy Checklist

- [ ] START marker: Small, understated, anchoring
- [ ] Step cards: Large, bold, interactive
- [ ] Connectors: Thin but visible, gradient adds direction
- [ ] END marker: Small, understated, closing
- [ ] FAB: Attention-grabbing, always accessible
- [ ] Header: Clear navigation, prominent save action
- [ ] Canvas: Maximum breathing room, centered content

---

## Accessibility

- FAB has `aria-expanded` state
- Popover has `role="menu"` with `aria-labelledby`
- Step cards have `role="listitem"` within `role="list"`
- Keyboard navigation: Tab through steps, Enter to expand, Arrow keys to reorder
- Focus trap when popover is open
- Reduced motion: Replace animations with opacity fades

---

## Summary of Key Changes

| Area | Before | After |
|------|--------|-------|
| **Creation Modal** | Inline cramped editor | Two-stage: quick config + full-screen builder |
| **Settings Modal** | Small modal with 350px max-height | Full-screen builder slide-in |
| **Add Step** | Inline collapsible palette taking layout space | Floating FAB with popover |
| **Step Cards** | Compact 16px padding | Spacious 24px padding |
| **Connectors** | 32px height | 48px height |
| **Pipeline Width** | 100% of container | Max 600px, centered |
