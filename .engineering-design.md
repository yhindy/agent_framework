# Engineering Design Document: Kanban Board Rework

## Overview

This document outlines the engineering plan to rework the Kanban board in the Minion Framework GUI application. The goal is to create accurate status transitions, make all cards clickable, unify the cleanup component, and add visual state indicators to cards.

## Acceptance Criteria

1. **Accurate Status Transitions**: Agents should automatically transition between Kanban statuses based on their actual state
2. **All Cards Clickable**: Clicking any card in any column should navigate to the agent view
3. **Unified Cleanup Component**: Create a shared cleanup component that both Dashboard and AgentView use
4. **Visual State Indicators on Cards**: Cards should show real-time working/waiting state with visual indicators
5. **Remove Code Duplication**: Consolidate the cleanup logic into one place

---

## 1. Architecture Overview

### Current State Flow

```
TerminalService (JSONL Polling)
    │
    ├── agent:stateChanged (working/waiting/unknown)
    │
    ▼
AgentService (.agent-info file)
    │
    ├── claudeState field
    ├── status field
    │
    ▼
IPC (agents:updated, assignments:updated)
    │
    ▼
Renderer (Dashboard, AgentView, Sidebar)
```

### Proposed State Flow

```
TerminalService (JSONL Polling)
    │
    ├── agent:stateChanged (working/waiting/unknown)
    │
    ▼
StatusTransitionService (NEW)  ◄── Centralizes transition logic
    │
    ├── Determines Kanban column based on:
    │   - Current status + claudeState + time thresholds
    │
    ▼
AgentService (.agent-info file)
    │
    ├── status (updated by transition service)
    │
    ▼
IPC (agents:updated)
    │
    ▼
Dashboard (Kanban board displays status)
```

## 2. Component Design

### 2.1 New: StatusTransitionService

**Purpose**: Centralize all status transition logic to ensure consistency between backend and frontend.

**File**: `gui/src/main/services/StatusTransitionService.ts`

```typescript
interface StatusTransitionConfig {
  waitingThresholdMs: number      // Time before in_progress+waiting -> review
  defaultState: ClaudeState       // Default if unknown
}

interface StatusTransitionService {
  // Trigger automatic transition if conditions met
  checkAndTransition(projectPath: string, agentId: string): Promise<boolean>

  // Manual user-initiated transitions
  moveToReview(projectPath: string, agentId: string): Promise<void>
  markCompleted(projectPath: string, agentId: string): Promise<void>
}

type KanbanStatus = 'in_progress' | 'review' | 'completed' | 'pr_open' | 'merged'
```

**Transition Rules**:

| Current Status | claudeState | Duration | New Status |
|----------------|-------------|----------|------------|
| in_progress    | working     | any      | in_progress (no change) |
| in_progress    | waiting     | < 5 min  | in_progress (no change) |
| in_progress    | waiting     | >= 5 min | review (auto-transition) |
| in_progress    | unknown     | any      | in_progress (no change) |
| review         | working     | any      | in_progress (return to working) |
| review         | any         | any      | review (stays) |
| completed      | any         | any      | completed (terminal) |
| pr_open        | any         | any      | pr_open (managed by PR flow) |
| merged         | any         | any      | merged (terminal) |

**Important Exclusions**:
- **Super Minions**: Auto-transitions do NOT apply to super minions (orchestrators). They have their own workflow: `planning` -> approval -> `orchestrating` -> `completed`. Super minions are identified by `isSuperMinion: true` in AgentInfo.
- **Non-Claude Tools**: Auto-transitions only apply to agents using the `claude` tool (which has JSONL state). For `cursor-cli` and `codex` tools, state detection uses pattern matching via IdleDetector, which sets `isWaitingForInput` but not `claudeState`. These agents can use manual transitions but not automatic time-based transitions.

## 3. State Transition Logic

### 3.1 Automatic Transitions

**Trigger Points**:
1. `agent:stateChanged` IPC event from TerminalService
2. Periodic check (every 60 seconds) for time-based transitions
3. PR status polling results (existing)

**Implementation**:

```typescript
// In StatusTransitionService
async checkAndTransition(projectPath: string, agentId: string): Promise<boolean> {
  const agentInfo = await this.agentService.readAgentInfo(worktreePath)

  // Guard: Skip if agent no longer exists
  if (!agentInfo) return false

  // Guard: Skip super minions (they have their own workflow)
  if ((agentInfo as any).isSuperMinion) return false

  // Guard: Skip non-Claude tools (no JSONL state)
  if (agentInfo.tool !== 'claude') return false

  // Guard: Skip terminal states
  if (['completed', 'merged', 'closed', 'pr_open'].includes(agentInfo.status)) return false

  // Migration: Initialize waitingSince for existing waiting agents
  if (agentInfo.claudeState === 'waiting' && !agentInfo.waitingSince) {
    await this.updateAgentInfo(worktreePath, { waitingSince: new Date().toISOString() })
    return false // Don't transition yet, start counting from now
  }

  // Rule 1: in_progress + waiting for extended period -> review
  if (agentInfo.status === 'in_progress' &&
      agentInfo.claudeState === 'waiting' &&
      agentInfo.waitingSince) {
    const waitingDuration = Date.now() - new Date(agentInfo.waitingSince).getTime()
    if (waitingDuration >= this.config.waitingThresholdMs) {
      // Re-read to ensure agent still exists and state hasn't changed
      const currentInfo = await this.agentService.readAgentInfo(worktreePath)
      if (!currentInfo || currentInfo.claudeState !== 'waiting') return false

      await this.updateStatus(projectPath, agentId, 'review')
      this.mainWindow.webContents.send('agents:updated')
      return true
    }
  }

  // Rule 2: review + working -> back to in_progress
  if (agentInfo.status === 'review' &&
      agentInfo.claudeState === 'working') {
    await this.updateStatus(projectPath, agentId, 'in_progress')
    this.mainWindow.webContents.send('agents:updated')
    return true
  }

  return false
}
```

### 3.3 Timestamp Tracking

Add `waitingSince` field to track when agent started waiting:

```typescript
// In TerminalService, when state changes to 'waiting'
if (currentState === 'waiting' && lastKnownState !== 'waiting') {
  this.updateAgentInfo(worktreePath, {
    isWaitingForInput: true,
    claudeState: 'waiting',
    waitingSince: new Date().toISOString()  // NEW
  })
}

// When state changes from 'waiting' to 'working'
if (currentState === 'working' && lastKnownState === 'waiting') {
  this.updateAgentInfo(worktreePath, {
    isWaitingForInput: false,
    claudeState: 'working',
    waitingSince: undefined  // Clear the timestamp
  })
}
```

## 7. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Time-based transitions fire incorrectly | Medium | Medium | Use explicit `waitingSince` timestamp, not derived from lastActivity |
| State indicator performance | Low | Low | Use React.memo, only update on state changes; debounce updates (200ms) |
| Cleanup dropdown z-index issues | Low | Low | Test in both scrollable (Dashboard) and fixed (AgentView) contexts |
| Breaking existing cleanup flows | Medium | High | Keep existing code working until new component fully tested |
| Race condition between polling and IPC | Medium | Low | Re-read agent info before writing transitions; skip recently checked agents |
| Migration for existing agents | Medium | Medium | Initialize `waitingSince` on first check if missing |
| Super minion auto-transition | Low | High | Explicit guard at top of checkAndTransition() |

## 7.1 Edge Cases Handled

1. **Agent deleted during transition**: Re-read agent info before writing; abort if null
2. **Existing agents without `waitingSince`**: Initialize on first check, don't transition immediately
3. **Super minions**: Explicitly excluded from auto-transitions
4. **Non-Claude tools**: Explicitly excluded from auto-transitions (Cursor/Codex use pattern matching, not JSONL)
5. **Agent stopped mid-transition**: Guard checks + re-read before write prevents orphaned state
