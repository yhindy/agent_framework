# Workflow Editor UX Design Specification

A bold, intentional UX design for customizing Super Minion workflows in the Agent Framework app.

---

## Design Philosophy

This isn't another drag-and-drop list editor with boring uniform cards. The Workflow Editor is a **command center** where users architect their AI orchestration strategy. Every visual element communicates the flow of execution, the relationships between steps, and the power the user wields over their agent army.

Key design principles:
- **Dramatic visual hierarchy** - The workflow isn't a list, it's a pipeline with clear directionality
- **Bold contrast** - Parallel vs sequential execution must be instantly distinguishable at a glance
- **Spatial intentionality** - White space separates phases; connection lines create visual rhythm
- **Dark-first drama** - Leverage the app's dark theme for theatrical glow effects and depth

## 2. Editor Panel: Slide-Out from Right

### Why Slide-Out vs Modal
- Modals are interruptive and hide context
- A slide-out panel keeps the Super Agent view visible
- Users can see both their current workflow and terminal activity
- Feels more "workspace-y" than a popup

### Panel Dimensions & Animation
```css
.workflow-panel {
  position: fixed;
  top: 0;
  right: 0;
  width: 480px;
  height: 100vh;
  background: var(--bg-surface);
  border-left: 1px solid var(--border-default);
  box-shadow: -8px 0 48px rgba(0, 0, 0, 0.5);
  z-index: var(--z-modal);
  transform: translateX(100%);
  transition: transform var(--transition-slow) cubic-bezier(0.16, 1, 0.3, 1);
}

.workflow-panel.open {
  transform: translateX(0);
}
```

### Panel Header
```
+----------------------------------------------------------+
|  [X]  WORKFLOW EDITOR                              [?]   |
|       Configure execution order for your Super Minion     |
+----------------------------------------------------------+
```

- Title: "WORKFLOW EDITOR" in uppercase, letter-spacing 0.1em, font-weight 700
- Subtitle: Muted text explaining purpose
- Close button (X) top-left - breaks convention intentionally (feels like closing a drawer)
- Help button (?) top-right for onboarding tooltip

## 3. The Pipeline View: Vertical Flow with Visual Connectors

### Core Concept: Steps as Nodes in a Pipeline

Reject the flat list. Each step is a **node** in a visual pipeline, connected by animated flow lines that show execution direction.

### Layout Structure
```
+------------------------------------------+
|  [HEADER]                                |
+------------------------------------------+
|                                          |
|  [STEP PALETTE]  (collapsed by default)  |
|                                          |
+------------------------------------------+
|                                          |
|  START                                   |
|    |                                     |
|    v                                     |
|  +------------------------------------+  |
|  |  1. EXPLORE                    [x] |  |
|  |     Search codebase for context    |  |
|  +------------------------------------+  |
|    |                                     |
|    v                                     |
|  +====================================+  |
|  ||  PARALLEL GROUP                  ||  |
|  ||                                  ||  |
|  ||  +------------+  +------------+  ||  |
|  ||  | 2. IMPL    |  | 3. IMPL    |  ||  |
|  ||  | Feature A  |  | Feature B  |  ||  |
|  ||  +------------+  +------------+  ||  |
|  ||                                  ||  |
|  +====================================+  |
|    |                                     |
|    v                                     |
|  +------------------------------------+  |
|  |  4. DEBUG                      [x] |  |
|  |     Run tests and fix issues       |  |

|    |                                     |
|    v                                     |
|  END                                     |
|                                          |
+------------------------------------------+
```

## 6. Drag and Drop Interactions

### Drag Feedback
When dragging a card:
1. Original position shows a **ghost placeholder** (dashed border, transparent)
2. Dragged card has elevated shadow and slight rotation
3. Valid drop zones glow with accent color

```css
.drop-zone-placeholder {
  background: var(--accent-primary-dim);
  border: 2px dashed var(--accent-primary);
  border-radius: var(--radius-lg);
  height: 80px;
  margin: var(--space-2) 0;
  animation: dropzone-pulse 1s ease-in-out infinite;
}

@keyframes dropzone-pulse {
  0%, 100% { opacity: 0.5; }
  50% { opacity: 1; }
}
```

### Drop Zone Indicators
Show where the step will land:
```css
.drop-indicator {
  height: 4px;
  background: var(--accent-primary);
  border-radius: 2px;
  margin: var(--space-1) 0;
  box-shadow: 0 0 12px var(--accent-primary-glow);
  animation: drop-indicator-glow 0.5s ease-in-out infinite;
}
```

### Reorder with Keyboard (Accessibility)
- Tab to focus a step card
- Space to "pick up" (visual indicator shows it's selected)
- Arrow keys to move position
- Enter to "drop"
- Escape to cancel

## Summary

This Workflow Editor design creates a **memorable, distinctive experience** through:

1. **Pipeline visualization** - Not a boring list, but a flowing execution diagram
2. **Bold color coding** - Each step type has unmistakable visual identity
3. **Theatrical transitions** - Glow effects, smooth animations, visual drama
4. **Clear parallel/sequential distinction** - Dashed borders and grouping make it obvious
5. **Inline editing** - No modal fatigue, everything happens in context
6. **Keyboard-first accessibility** - Power users can fly through it

The design extends the existing app's dark, professional aesthetic while adding the visual punch needed for a complex orchestration interface.
